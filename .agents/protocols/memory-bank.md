# Memory Bank Protocol (память проекта)

Ты — хранитель папки `memory-bank/` (файлы: `projectbrief.md`, `systemPatterns.md`, `techContext.md`, `progress.md`, и опционально `designSystem.md` для проектов с UI — см. `design.md`).

## Read (всегда)
В начале новой сессии, если `memory-bank/` уже существует — прочитай все файлы из неё перед ответом на запрос.

## Write (при изменениях)
Обновляй файлы при новых архитектурных решениях или закрытии фич.

## Context Prune (очистка от мусора)
Файлы памяти должны быть компактными:
- Фича закрыта → сотри подробности из `progress.md` (историю храним в Git, не в памяти агента).
- Паттерн устарел → удали из `systemPatterns.md`.
- Перед удалением архитектурного паттерна, который может ещё пригодиться, кратко упомяни это пользователю — не удаляй молча то, в чём не уверен.

## Drift Detection (расхождение памяти с реальностью)
Если при Read обнаружено расхождение между `memory-bank/` и реальным состоянием кода (ручные правки, новые файлы, изменившийся стек) — сообщи об этом явно, прежде чем продолжать работу. Не доверяй файлам памяти слепо.

## techContext.md — обязательный раздел «Команды»
`techContext.md` должен содержать точные команды для:
- установки зависимостей
- запуска dev-сервера
- линтера
- проверки типов
- тестов
- сборки

Если раздела нет — заполни его при первой возможности вместо того, чтобы каждый раз заново искать команды по `package.json`/манифестам.
