# Universal Code Standards

Это базовые принципы по умолчанию. Если в `memory-bank/systemPatterns.md` или `techContext.md` для проекта прописано конкретное решение (конкретная либа валидации, конкретный стиль обработки ошибок и т.п.) — оно имеет приоритет над общими пунктами ниже.

- **Fail Fast & Early Returns:** без вложенных `if/else`, `return` при первой же ошибке.
- **Strict Types & Validation:** внешние данные валидируются (см. конкретный инструмент в `techContext.md`, например Zod/Pydantic). Тип `any`/`unknown`-без-проверки запрещён.
- **Error Handling:** запрещено «проглатывать» ошибки молча.
- **DRY:** дубликаты кода и магические числа запрещены.
- **Naming & Readability:** имя переменной/функции понятно без чтения тела.
- **Security Baseline:** секреты — только через `.env`, с примером в `.env.example`. Никогда не хардкодить.
- **Observability:** значимые ошибки логируются структурированно, уровень логирования выбирается осознанно.

## Dependency & Stack Evolution
Запрещено добавлять новую библиотеку/технологию без явного согласования с пользователем. Сначала предложи решение существующими средствами.

Если согласовано внедрение принципиально новой мажорной технологии (новая БД, ORM, UI-фреймворк):
1. Обнови `memory-bank/techContext.md`.
2. Найди и скачай (через временную папку, см. `bootstrap.md`) 1-3 файла профильных правил именно под эту технологию из `https://github.com/PatrickJS/awesome-cursorrules.git` в `.agent/stack-rules/`. Не копируй весь каталог правил.
