# Bootstrap Protocol

## Универсальная команда входа: `ag-start`
Когда пользователь пишет `ag-start` отдельным сообщением — выполни:

1. **Detect Project State:** проверь, существует ли `memory-bank/`, есть ли в проекте код.
2. **Route by state:**
   - Пустой проект + нет `memory-bank/` → Init (холодный старт, пустой проект).
   - Есть код + нет `memory-bank/` → Init (холодный старт, существующий проект).
   - Есть `memory-bank/` → прочитай все файлы (`memory-bank.md`), выполни Drift Detection, **дополнительно проверь**, существуют ли `.agent/skills/` и `.agent/stack-rules/` и не пусты ли они. Если отсутствуют или пусты — сообщи об этом явно и предложи выполнить Auto-Bootstrap сейчас (тот же шаг, что в Init, см. ниже), прежде чем продолжать. Затем кратко (3-5 строк) резюмируй состояние проекта («Вот что я помню: …») и спроси, что делаем дальше.
3. После Detect Project State — жди описание задачи, затем выбирай Fast-track или Full Pipeline (`pipeline.md`).

## Init — пустой проект (нет memory-bank, нет кода)
1. **Auto-Bootstrap (только универсальные скиллы):** если нет `.agent/skills/` и `.agent/stack-rules/` — создай (`mkdir -p .agent/skills .agent/stack-rules`, вторая пока пустая).
   Клонируй `https://github.com/mattpocock/skills.git` во временную папку (`/tmp/agent-setup`), скопируй файлы скиллов (`grill-me.md`, `design-an-interface.md`, `tdd.md`) в `.agent/skills/`. Эти файлы не зависят от стека, поэтому качаем их сразу. Удали временную папку.
   Если репозиторий недоступен — сгенерируй эталонное содержимое файлов самостоятельно.
2. Создай базовую структуру `memory-bank/`.
3. Задай вопросы о сути проекта (для кого, что делает, ключевые сценарии), чтобы заполнить `projectbrief.md`.
4. **Выбор стека:** на основе ответов предложи 2-3 варианта стека технологий в простых словах, без узкоспециальных терминов там, где можно обойтись:
   - для каждого варианта — 1-2 предложения плюсов и минусов применительно к именно этому проекту (не общие абстрактные плюсы фреймворка).
   - дождись, пока пользователь выберет один из вариантов (или явно попросит другой стек, не из предложенных).
   - зафиксируй выбор в `memory-bank/techContext.md`, включая раздел «Команды» (см. `memory-bank.md`) — как только определятся реальные команды проекта (после первого `npm init`/аналога).
5. **Stack-rules (только теперь, когда стек известен):** клонируй `https://github.com/PatrickJS/awesome-cursorrules.git` во временную папку, выбери ТОЛЬКО 1-3 файла под выбранный стек, переименуй понятно (`web.md`, `backend.md`) и скопируй в `.agent/stack-rules/`. Категорически не копируй весь каталог. Удали временную папку. Если репозиторий недоступен — сгенерируй эталонное содержимое сам.
6. **Git & GitHub Setup** (детали — `git-workflow.md`), теперь, когда `memory-bank/` реально заполнена:
   - `git init`, `git branch -M main`, `git add .`, `git commit -m "feat: начальная структура проекта и memory-bank"`.
   - Проверь `gh auth status`. Если ок — спроси: «Создать удалённый репозиторий на GitHub и запушить код?». При «да»: `gh repo create <имя-папки> --private --source=. --remote=origin --push`.
7. Не пиши код приложения, пока не закрыты пункты 3-5.

## Init — существующий проект (нет memory-bank, но есть код)
1. **Быстрое определение стека:** просмотри манифесты (package.json/requirements.txt/go.mod/Cargo.toml и т.п.), чтобы понять стек проекта — этого достаточно для следующего шага, полный анализ будет позже.
2. **Auto-Bootstrap:** создай `.agent/skills/` и `.agent/stack-rules/`, если их нет.
   - Скиллы (`grill-me.md`, `design-an-interface.md`, `tdd.md`) — клонируй `https://github.com/mattpocock/skills.git` во временную папку, скопируй в `.agent/skills/`.
   - Stack-rules — теперь, когда стек определён на шаге 1: клонируй `https://github.com/PatrickJS/awesome-cursorrules.git`, выбери ТОЛЬКО 1-3 файла под определённый стек, скопируй в `.agent/stack-rules/`. Категорически не копируй весь каталог.
   - Удали временную папку. Если репозитории недоступны — сгенерируй эталонное содержимое сам.
3. **Git & Remote Check** (детали — `git-workflow.md`):
   - Нет `.git` → `git init`, `git branch -M main`, `git add .`, `git commit -m "feat: исходное состояние существующего проекта"`.
   - Проверь `git remote -v`:
     - `origin` уже есть → используй его, новый репозиторий не создавай.
     - `origin` нет → проверь `gh auth status`, спроси: «Создать удалённый репозиторий на GitHub и привязать к проекту?». При согласии: `gh repo create <имя-папки> --private --source=. --remote=origin --push`.
4. Проанализируй структуру проекта подробно (манифесты зависимостей, файлы, паттерны, реальный стек). Заполни `techContext.md` (включая раздел «Команды», см. `memory-bank.md`) и `systemPatterns.md`.
5. Покажи черновик найденных паттернов для подтверждения. Задай уточняющие вопросы по неясному из кода (для `projectbrief.md`), прежде чем писать новый код.
