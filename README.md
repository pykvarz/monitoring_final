# Network Monitor

**Network Monitor** — высокопроизводительное десктопное Windows-приложение для мониторинга доступности сетевых узлов и ИТ-инфраструктуры в реальном времени. Разработано как автономный рабочий инструмент для системных администраторов, сетевых инженеров и специалистов технической поддержки.

Поставляется в виде автономного переносимого `.exe`-файла для Windows (не требует прав локального администратора) либо запускается из исходного кода Python.

## Ключевые возможности

### ⚡ Параллельный мониторинг и нативный Win32 ICMP-движок
- **Нативный Win32 ICMP-движок**:
  - Прямое взаимодействие с Win32 API `iphlpapi.dll` (`IcmpSendEcho` для IPv4 и `Icmp6SendEcho2` для IPv6) через модуль `ctypes`.
  - Работает на полной скорости прямо внутри процесса **без прав локального администратора** и без запуска дочерних процессов `ping.exe`.
  - Отсутствие микрофризов и полная совместимость с корпоративными EDR/антивирусами (Kaspersky Endpoint Security, Defender ATP и др.), перехватывающими порождение процессов.
  - Точная валидация ICMPv6: проверка поля `Status == 0` (`IP_SUCCESS`) в структуре `ICMPV6_ECHO_REPLY` исключает ложноположительные статусы при получении ICMPv6-пакетов ошибок.
  - Прозрачный системный фоллбэк на штатную утилиту `ping` для не-Windows окружений.
  - Внешняя зависимость `ping3` полностью удалена из проекта (нулевой риск уязвимостей внешних пинг-пакетов).
- **Многопоточный опрос**: параллельный пинг пула узлов с помощью `ThreadPoolExecutor` с настраиваемым количеством рабочих потоков (от 1 до 100).
- **Поддержка сетевой адресации**:
  - IPv4 и IPv6 адреса.
  - FQDN (доменные имена).
  - Однокомпонентные сетевые имена локальной сети (`localhost`, `router`, `dc01`, `nas`, `sw-core`).
- **Статус-машина узлов**:
  - Чёткие состояния: `ONLINE` ➔ `WAITING` (временный сбой) ➔ `OFFLINE` (авария) / `MAINTENANCE` (регламентные работы).
  - Настраиваемые пороги таймаутов перехода в `WAITING` и `OFFLINE`.
  - Throttling контрольных отметок: запись `last_seen` в базу данных выполняется не чаще 1 раза в 60 секунд для минимизации нагрузки на диск.
- **Точный учёт времени простоя**:
  - Фиксация реального момента падения (`offline_since`).
  - Человекочитаемое форматирование времени недоступности («X д Y ч Z мин», «X ч Y мин», «< 1 мин»).

### 📁 Управление группами узлов
- **Полнофункциональный менеджер групп** (`Ctrl+G` / кнопка на панели быстрых действий):
  - Просмотр списка групп с отображением реального количества хостов в каждой группе.
  - Создание новых пользовательских групп.
  - Пакетное переименование групп с автоматическим транзакционным обновлением всех связанных хостов в SQLite и сохранением в конфигурации.
  - Безопасное удаление группы с автоматическим переносом узлов в системную группу по умолчанию.
  - Защита системной группы «Без группы» от случайного удаления или переименования.
- **Быстрая фильтрация**: удобный выпадающий список на панели инструментов для моментальной фильтрации хостов по выбранной группе.

### 🎫 Интеграция с Helpdesk (Naumen Service Desk / GWT)
- **Автоматизация на базе Playwright**:
  - Запуск через системный браузер Microsoft Edge или Chrome без необходимости отдельной установки бинарников Chromium (`playwright install`).
  - Очередь сессий (`asyncio.Semaphore(1)`) для предотвращения конфликтов при быстрых повторных кликах оператора.
- **Сценарии обслуживания**:
  - Ручное создание и закрытие заявок из контекстного меню; пункты активируются только для узлов из группы банкоматов: `АТМ`, `ATM`, `Банкоматы`.
- **Интеллектуальное автозаполнение полей**:
  - Автоматическое форматирование номера банкомата с добавлением префикса `0000` (например, `1234` ➔ `00001234`) с защитой от дублирования префикса в полях «Местонахождение», «Тема» и «Описание».
  - Подстановка готовых причин с возможностью ввода собственной версии и её автосохранением в список постоянных причин в `config.json`.
  - Точные селекторы формы GWT Naumen SD (`#gwt-debug-apply`, `.g-button:has-text('Сохранить')`) с явным ожиданием готовности DOM (`wait_for(state="visible")`).
- **Гибкие режимы работы**:
  - **Видимый режим** (по умолчанию): наглядный визуальный контроль оператором открытия окна, заполнения полей и отправки заявки.
  - **Фоновый (Headless) режим**: скрытая работа без отображения окон браузера (переключается в «Настройках»).
- **Безопасность**: скриншоты ошибок сохраняются в системный временный каталог (`tempfile.gettempdir()`) с уникальным именем хоста, предотвращая засорение диска и ошибки `PermissionError`.

### 🖥️ Современный UI и дизайн-система
- **Две темы оформления**:
  - **Dark (по умолчанию)**: сбалансированная тёмная палитра для снижения утомляемости глаз при круглосуточном мониторинге.
  - **Tactical (NOC Terminal)**: высококонтрастный режим центра управления сетью с моноширинным шрифтом `Consolas` и неоновыми индикаторами.
- **Векторная графика**: строго контурные SVG-иконки Lucide (`stroke-width="2"`), отсутствие цветных системных эмодзи и визуального шума.
- **Адаптивная таблица хостов**:
  - Автоматическое распределение ширины колонок без пустых зон справа.
  - Деликатная статусная цветовая подсветка строк.
  - Сохранение порядка, ширины и видимости колонок в конфигурации.
  - Контекстное меню заголовков таблицы для скрытия/отображения столбцов (с защитой колонки «Название»).
  - Быстрая фильтрация таблицы `O(1)` с технологией Early Exit и точечным управлением видимостью строк.
- **Плавающее HUD-окно журнала событий (Always on Top)**:
  - Панель оперативных событий (`EventLogPanel`) открепляется в компактное плавающее окно с режимом «Поверх всех окон».
  - Сохранение экранных координат, геометрии и статуса открепления между перезапусками приложения.
  - Оптимизированный рендеринг: лимит до 30 последних событий и отвязка от тиков мониторинга для исключения фризов UI.
- **Desktop Toast-уведомления**:
  - Всплывающие карточки в правом нижнем углу экрана с аппаратной прозрачностью Windows DWM, мягкими тенями и звуковым сигналом.
  - Возможность индивидуального отключения уведомлений для конкретного узла.
- **Кастомный стиль элементов**:
  - Выпадающие списки `QComboBox` раскрываются строго вниз благодаря переопределению хинта `SH_ComboBox_Popup = 0` через `QProxyStyle`.
  - Безупречная стилизация диалогов, кнопок и списков в тёмных темах без нестилизованных белых артефактов.

### 🛠️ Контекстные меню и операции
- **Контекстное меню отдельного узла**:
  - **Пинг в CMD**: запуск непрерывного пинга (`ping -t`) в отдельном окне командной строки Windows с санитизацией заголовка от метасимволов `cmd.exe`.
  - **Пинг Cisco (IP-1)**: автоматический расчёт и пинг шлюза/коммутатора (уменьшение последнего октета IPv4 на 1).
  - **Редактировать / Удалить**: быстрый доступ к параметрам хоста.
  - **Тех.обслуживание**: перевод узла в режим `MAINTENANCE` (приостановка фиксации аварий и уведомлений).
  - **Включить / отключить уведомления**: персональное управление нотификациями для узла.
  - **Helpdesk: открыть / закрыть заявку**: интеграция для банкоматов группы АТМ.
- **Массовые (пакетные) действия над выбранными узлами**:
  - Переключение режима тех.обслуживания для группы хостов.
  - Пакетное перемещение в другую группу.
  - Массовое включение/отключение уведомлений.
  - Групповое удаление.

### 💾 Надёжное хранение данных (SQLite WAL)
- **База данных `hosts.db`**:
  - Режим `Write-Ahead Logging` (WAL), гарантирующий сохранность данных и устойчивость к сбоям питания.
  - Автоматические версионированные миграции схемы базы данных (`schema_version`).
  - Индексация по статусам, группам и времени событий.
- **Потокобезопасность**:
  - Фоновый воркер `MonitorThread` изолирован от GUI-потока и использует выделенное именованное SQLite-соединение (`monitor_thread_{id}`).
  - Обновление интерфейса происходит строго через сигналы Qt с подавлением дребезга (debounce 250 мс).
- **Журнал истории статусов** (`status_history`):
  - Фиксация переходов состояний с фильтрацией по датам, статусам, группам и тексту (`Ctrl+H`).
  - Автоматическая ротация устаревших записей журнала (настраиваемый срок хранения, по умолчанию 90 дней).
- **Надёжные пути к данным**:
  - Привязка файлов `hosts.db`, `config.json` и `debug.log` к базовой директории приложения (`base_dir`), исключающая сброс путей при запуске из ярлыка Windows с произвольным CWD.

### 📊 Импорт и экспорт в Excel
- Массовый импорт и экспорт базы узлов в формате Excel (`.xlsx`) через библиотеку `openpyxl`.
- **Защита от Formula Injection / CSV Injection (CWE-1236)**: автоматическое безопасное экранирование ячеек с управляющими префиксами (`=`, `+`, `-`, `@`, `\t`, `\r`).

## Горячие клавиши

| Сочетание клавиш | Действие |
|------------------|----------|
| `Ctrl + Space`   | Пауза / возобновление мониторинга сети |
| `Ctrl + H`       | Открыть общий журнал истории событий |
| `Ctrl + G`       | Открыть менеджер групп узлов |
| `Ctrl + N`       | Добавить новый узел |
| `Ctrl + P`       | Открыть диалог настроек приложения |
| `Ctrl + I`       | Импорт списка узлов из Excel (`.xlsx`) |
| `Ctrl + E`       | Экспорт текущего списка узлов в Excel (`.xlsx`) |
| `F5`             | Принудительно запустить опрос всех узлов прямо сейчас |
| `Delete`         | Удалить выбранный узел (или группу выделенных узлов) |
| `Esc`            | Сброс фильтров поиска / закрытие диалоговых окон |

## Установка и запуск

### Требования
- Операционная система: **Windows 10 / 11**
- Python: **3.10+** (протестировано на Python 3.14)

### 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

*(Для запуска тестов и сборки дистрибутива):*
```bash
pip install -r requirements-dev.txt
```

### 2. Конфигурация (опционально)
Все настройки хранятся в `config.json` рядом с исполняемым файлом (создаётся автоматически при первом запуске). Отредактируйте его вручную или через интерфейс «Настройки» в приложении.

Для подробного логирования запустите с флагом `--debug`:
```bash
python main.py --debug
```

### 3. Запуск приложения
```bash
python main.py
```

### 4. Запуск тестов
В проекте есть автоматические unit-, integration- и regression-тесты:
```bash
pytest
```
Подробный вывод с перечислением тестовых наборов:
```bash
pytest -v
```

### 5. Сборка автономного исполняемого файла (.exe)
Сборка переносимого дистрибутива `NetworkMonitor.exe` выполняется командой:
```bash
python build_exe.py
```
Собранный исполняемый файл будет помещён в директорию `dist/`.

## Безопасность

Проект разработан с соблюдением строгих корпоративных стандартов информационной безопасности:
- Принцип наименьших привилегий (не требуются права Администратора).
- Защита от Formula Injection (CWE-1236) при работе с Excel.
- Защита от Command Injection при запуске утилит терминала Windows.
- Безопасное хранение скриншотов во временном каталоге ОС.
- Потокобезопасная изоляция транзакций SQLite WAL.
- Отсутствие скрытой телеметрии и сторонних сетевых запросов.

Подробный отчет по безопасности см. в документе [SECURITY.md](SECURITY.md).
